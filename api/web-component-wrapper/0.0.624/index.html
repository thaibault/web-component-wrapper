Project Status

Use case

Write web components with little code or turn existing React components into web components. Attributes are converted into typed properties, callbacks of the component become DOM events and templates are re-rendered when properties change. The resulting custom elements work in plain HTML and in any framework.

Content

Installation

npm install web-component-wrapper clientnode core-js

Wrapping React components additionally needs "react" and "react-dom". The bundle "web-component-wrapper/bundle" already contains all dependencies, including React, and can also be loaded from a CDN like "https://unpkg.com/web-component-wrapper@latest/dist/bundle/index.js". For older browsers use the "compatible" variants.

Own web components

Derive from "Web", set "doRender" and describe the markup in "content". Expressions in "${...}" see all properties and are evaluated again whenever a property changes. "property" declares a property, its attribute is the name in kebab case:

import {string} from 'clientnode/property-types'
import {property, Web} from 'web-component-wrapper'

class MyGreeting extends Web {
    static doRender = true
    // NOTE: No template literal, "${...}" is evaluated when rendering.
    static content =
        '<button bind-on-click="self.greetingName = \'you\'">' +
        'Hello ${greetingName}!' +
        '</button>'
}
property({type: string})(MyGreeting.prototype, 'greetingName')

customElements.define('my-greeting', MyGreeting)

<my-greeting greeting-name="World"></my-greeting>

Values are inserted as HTML, so do not render untrusted input this way. With TypeScript you can use "@property" as decorator on class fields. Then call "this.defineGetterAndSetterInterface()" in the constructor, since class field initialization would otherwise overwrite the generated accessors.

Wrapping React components

"wrapAsWebComponent" turns a React component into a web component. Its "propTypes" define the properties. Callbacks like "onChange" are dispatched as DOM events ("change"):

import {func, number, string} from 'clientnode/property-types'
import {createElement} from 'react'
import {wrapAsWebComponent} from 'web-component-wrapper'

const Counter = ({count = 0, label = 'Clicks', onChange}) =>
    createElement(
        'button',
        {onClick: () => onChange?.({count: count + 1})},
        `${label}: ${count}`
    )
Counter.propTypes = {count: number, label: string, onChange: func}

wrapAsWebComponent(
    Counter,
    'Counter',
    {
        controllableProperties: ['count'],
        propertiesToReflectAsAttributes: {count: number}
    }
).register('my-counter')

<my-counter count="2" label="Votes"></my-counter>

<script>
    document.querySelector('my-counter').addEventListener(
        'change', (event) => console.log(event.detail.parameters[0].count)
    )
</script>

An object passed to a callback updates the matching properties. "controllableProperties" lists those the web component manages itself, so the button counts up without any surrounding code. "propertiesToReflectAsAttributes" writes them back as attributes. Further options:

  • "eventToPropertyMapping": Maps callback arguments to properties per event, e.g. {onChange: (value) => ({value})}.
  • "propertyAliases": Alternative property names.
  • "internalProperties": Fixed properties passed to the React component.
  • "propTypes": Property types if the component does not define them.

"register" without argument derives the tag name from the component name, e.g. "TextInput" becomes "text-input". Since tag names need a hyphen, single words get the prefix "web-", e.g. "Counter" becomes "web-counter".

Attributes and properties

The type of a property decides how its attribute is read:

  • "string": Taken as it is.
  • "boolean": Set by the presence of the attribute.
  • "func": The attribute value is a function body. "event" and "parameters" hold the arguments of a call.
  • All other types, like "number", "object" or "array": Evaluated as JavaScript expression.

For a component with the properties "title" (string), "highlighted" (boolean), "options" (object) and "onSelect" (func):

<my-card
    highlighted
    on-select="console.log('Selected', parameters)"
    options="{size: 2 * 21}"
    title="Welcome"
></my-card>

Setting a property via JavaScript ("element.title = 'New'") renders again as well.

Bindings in templates

Elements inside "content" can bind to the component, and so can the component's own element in HTML. Expressions see the properties, "self" (the component), "parentInstance", "rootInstance" and for events "event" and "parameters":

  • "bind-on-<event>": Runs code on an event, e.g. "bind-on-click".
  • "bind-attribute-<name>": Sets an attribute to the expression's value.
  • "bind-property-<name>": Sets a DOM property to the expression's value.
<my-counter
    bind-on-change="console.log(event.detail.parameters[0].count)"
></my-counter>

Each of them can also be written with a "data-" prefix to keep the markup valid HTML.
